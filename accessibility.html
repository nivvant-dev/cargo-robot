Accessibility Statement

Last updated: October 24, 2026 · Self-assessed

This project should be usable by reviewers, students, teachers and visitors with a wide range of abilities and devices. This page explains what we have done, where the site still falls short, and how to tell us about a problem.

Short version: The site is built with WCAG 2.2 Level AA in mind, keyboard access and reduced motion, and has been checked by hand. It has not been independently audited. Known gaps are listed below, and we want to hear about anything we missed.

1. Our commitment

The Internal Cargo Unloading Robot is a student project for the NASA HUNCH program. We want the project story, design data, build steps, bill of materials and safety guidance to be available to everyone, including people who use a keyboard, a screen reader, a screen magnifier, voice control or a phone.

Accessibility is treated as part of the build, not an afterthought: the page uses semantic HTML, visible focus, text alternatives and responsive layout, and the interactive parts were exercised with the keyboard as well as the mouse.

2. Conformance status

This website is designed to meet the Web Content Accessibility Guidelines (WCAG) 2.2 Level AA. It has been self-assessed rather than certified or independently audited. We do not claim formal conformance, and we list the areas we know need work instead of overstating the result.

WCAG is published by the W3C. The guidelines explain how to make web content more accessible to people with disabilities: W3C WCAG overview.

3. What we have done

Accessibility measures by area
Area Measure
Structure Semantic landmarks (header, nav, main, footer), one page h1, ordered headings, a skip link, descriptive page titles and language set to English.
Keyboard All controls are reachable by keyboard with a visible focus ring. The mobile menu closes with Escape, the accordion uses native buttons, and the image lightbox traps focus, closes with Escape and returns focus to the image that opened it.
Images Every project image has descriptive alt text; decorative graphics are hidden from assistive technology. Captions explain what each diagram shows.
Charts & tables The trial chart has a text summary and an accessible name. The trial table contains the same data, so nothing is available only as a picture of a chart.
Colour & contrast Body text and controls meet contrast targets on the dark background. Results and states use text labels as well as colour, so success and failure do not rely on green or red alone.
Motion The demo sequence does not auto-play when your system requests reduced motion. It can be paused, stepped or replayed at any time. Other animations are short and non-essential.
Forms The trial form has visible labels, sensible input types, an inline error message with role="alert", aria-describedby links on the fields, aria-invalid on the field that needs attention, and focus moved to that field. Success is announced politely.
Zoom & reflow Layouts reflow at phone widths and remain usable when text is enlarged. Content does not require horizontal scrolling at 320 CSS pixels, apart from wide data tables that can scroll inside their own container.
Privacy by design No third-party scripts, analytics, ads, embedded players or tracking cookies. There are no pop-ups, interstitials or timed warnings.

4. Known limitations

We would rather be honest than claim perfection. These are the current gaps:

  • Source diagrams are low resolution. The supplied images are small screenshots. Their captions and the surrounding text carry the important information; higher-resolution originals can be supplied on request.
  • Some features need JavaScript. The bill of materials filter, demo stepper and trial log are interactive. The main project narrative, design summary, images, safety notes and build steps still work without it, but the BOM tables and test log will not populate. Contact us for a plain-text BOM if you need one.
  • The chart is drawn on a canvas. Screen readers get the summary figures and the full trial table instead. The canvas itself is marked as an image with a description and is not the only source of any result.
  • The site is in English only. We have not provided translations or a language switcher.
  • No independent audit. Testing was done by the team with browser tools and keyboard checks. It did not include a full screen-reader audit across every browser/assistive-technology combination.
  • External links are outside our control. The hosting providers' privacy pages and other linked resources may have their own accessibility issues.

5. Feedback and alternative formats

If any part of this site is hard to use, please tell us. Helpful details include the page address, what you were trying to do, what happened, and the browser or assistive technology you use. We will try to fix the issue or provide the information in another format, such as plain text, a larger-print version or a description read aloud.

Email berryda@cfbisd.edu with the subject “Accessibility”. If email is difficult, ask your teacher or mentor to pass the message to the team. We aim to acknowledge feedback during the school term, though this is a student project and response times may vary around exams and holidays.

Please do not include sensitive personal information in an accessibility report. The page address and a description of the barrier are enough.

6. How this statement was prepared

This statement was prepared by the project team on October 24, 2026. The site was reviewed by hand at desktop, tablet and phone widths, using the browser's accessibility tree, keyboard-only navigation and focus checks. Automated checks were used as a supplement, not as proof of conformance.

The review covered the home page and the policy pages. It included the mobile navigation, accordion, image lightbox, bill of materials filters, demo stepper and the trial log. We will update this statement if the site changes or if new issues are found.

7. Technical compatibility

The site is intended for current versions of Chrome, Edge, Firefox and Safari on desktop and mobile. It uses standard HTML, CSS and JavaScript, including <dialog> and inert for the lightbox; very old browsers may not support every interactive feature, but the written content remains available.

The site is designed to work without a mouse, at enlarged text sizes, and with the operating system's reduced-motion and forced-colours settings. Keyboard navigation and reduced-motion behaviour were checked, and forced-colours fallbacks are included for the gradient title and policy navigation. If your browser or device behaves differently, please let us know so we can investigate.
